# PA3 구현 보고서

학번: 2021312344

과제명: PA3 - Multi-threaded Seat Reservation Server/Client

제출 파일: 2021312344_pa3.tar.zst, 2021312344_pa3.pdf


## 1. 프로젝트 개요

본 과제의 목표는 기존 skeleton code를 기반으로 TCP socket을 사용하는 좌석 예약 서버와 클라이언트를 완성하는 것이다. 서버 프로그램은 pa3_server이고, 클라이언트 프로그램은 pa3_client이다. 서버는 1번부터 100번까지 총 100개의 좌석을 관리하며, 여러 클라이언트가 동시에 접속하여 login, book, confirm-booking, cancel-booking, logout, query 명령을 수행할 수 있어야 한다.

Skeleton code에는 Request, Response, SeatStats, Seat 같은 기본 자료구조와 error code, safe_read, safe_write, 일부 response 출력 함수, Makefile 구조가 제공되어 있었다. 그러나 실제 socket 연결, request/response 전송, server poll loop, worker thread 처리, 사용자 관리, 좌석 예약 처리, action별 handler 대부분은 직접 구현해야 하는 상태였다. 따라서 본 구현은 skeleton의 구조를 유지하면서 비어 있던 핵심 로직을 채우는 방식으로 진행하였다.

설계의 핵심은 세 가지이다. 첫째, 여러 client를 동시에 처리하기 위해 서버를 main thread와 worker thread 구조로 나누었다. 둘째, 사용자 배열과 좌석 배열을 여러 thread가 공유하므로 mutex를 이용해 race condition을 막았다. 셋째, client와 server 사이에서는 포인터가 포함된 구조체를 그대로 보내지 않고, field 단위로 데이터를 전송하도록 구현하였다.


## 2. Skeleton 기반 구현 범위

제공된 skeleton은 common, server, client, include 디렉터리로 나뉘어 있었다. include에는 Request와 Response 구조체, Action enum, Seat와 SeatStats 구조체, error code가 정의되어 있었다. common에는 safe_read, safe_write, default_request, free_request, free_response 같은 공통 함수가 있었다. client에는 입력 parsing과 response 출력의 일부 구조가 있었고, server에는 poll set, thread, request handler를 채워 넣어야 하는 형태의 함수들이 있었다.

본 구현에서 가장 많이 채운 부분은 server/pa3_server.c와 server/handle_request.c이다. pa3_server.c에서는 add_to_pollset, remove_from_pollset, thread_func, request 수신, response 전송, 비정상 연결 제거 로직을 구현하였다. handle_request.c에서는 login, book, confirm-booking, cancel-booking, logout, query의 실제 서버 동작을 구현하였다.

server/helper.c와 server/helper.h도 skeleton을 보완하였다. 사용자 배열 초기화, 사용자 추가, 좌석 배열 초기화, PollSet 생성, 적절한 PollSet 선택, worker 깨우기, 종료 시 cleanup, Argon2 password hash/verify 로직을 구현하거나 보강하였다. 특히 PollSet에는 fd별 active user를 기억하기 위해 active_users 배열을 추가하였다.

client 쪽에서는 pa3_client.c의 get_socket, send_request, receive_response, terminate를 구현하였다. helper.c에서는 입력 문자열을 Request로 변환하는 parse_request와 action 문자열을 Action enum으로 바꾸는 to_action을 보완하였다. handle_response.c는 대부분 제공된 형식을 유지하되, active user 관리와 query/confirm-booking 출력 처리에 필요한 부분을 정리하였다.


## 3. 클라이언트와 서버 통신 설계

Skeleton의 Request와 Response 구조체에는 char pointer가 포함되어 있다. 이 포인터 값은 한 프로세스 안에서만 의미가 있으므로, 구조체 전체를 그대로 socket으로 보내면 안 된다. 따라서 client와 server가 같은 순서로 field를 따로 보내고 받도록 설계하였다.

Request는 action, username_length, data_size를 먼저 보낸다. username_length가 0보다 크면 username 문자열을 이어서 보내고, data_size가 0보다 크면 data 문자열을 이어서 보낸다. 서버는 같은 순서로 읽으며, 길이 정보를 먼저 받기 때문에 필요한 크기만큼 메모리를 할당한 뒤 실제 문자열을 받을 수 있다.

Response도 같은 방식으로 처리한다. 서버는 response code와 data_size를 먼저 보내고, data_size가 있는 경우에만 response data를 전송한다. confirm-booking은 좌석 번호 배열을 response data로 보내고, query는 SeatStats 구조체를 response data로 보낸다. 클라이언트는 response code를 먼저 보고 성공 또는 실패 메시지를 출력하며, 필요한 경우 data를 알맞은 자료형으로 해석한다.

TCP에서는 read나 write가 한 번에 모든 바이트를 처리한다는 보장이 없다. 그래서 skeleton에서 제공된 safe_read와 safe_write를 모든 socket 통신에 사용하였다. 이 함수들은 부분 read/write가 발생하면 남은 바이트를 계속 처리하고, signal로 인해 EINTR이 발생하면 다시 시도한다.


## 4. 서버 구현

서버는 main thread와 worker thread들로 구성된다. main thread는 listening socket과 standard input을 poll로 감시한다. listening socket에 새 client connection이 들어오면 accept로 socket을 얻고, find_suitable_pollset으로 현재 client 수가 가장 적은 worker thread를 선택한다. 선택된 worker의 PollSet에 client socket을 추가한 뒤 pipe를 통해 worker를 깨운다.

Worker thread 수는 get_num_cores로 얻은 CPU core 수에 맞추어 생성하였다. 각 worker thread는 자신만의 PollSet을 가지고, 이 PollSet 안의 client socket들을 poll로 감시한다. PollSet의 첫 번째 fd는 worker를 깨우기 위한 pipe read end이고, 그 뒤에는 client socket들이 들어간다.

PollSet은 main thread와 worker thread가 함께 접근하므로 mutex로 보호한다. 다만 socket read/write 중 PollSet mutex를 잡고 있으면 다른 thread가 PollSet을 갱신하지 못하므로, worker는 PollSet을 local array로 복사한 뒤 mutex를 해제하고 poll을 수행한다. 실제 request를 처리하기 전에는 fd가 아직 PollSet에 남아 있는지 다시 확인한다.

Client socket에서 data가 들어오면 worker는 receive_request로 Request를 만들고 handle_request를 호출한다. handle_request는 action 종류에 따라 각 handler로 분기한다. 처리 결과는 Response에 담아 send_response로 client에게 보낸다. client가 종료되거나 socket error가 발생하면 remove_from_pollset으로 fd를 제거하고, active user가 있으면 서버의 logged_in 상태도 false로 되돌린다.


## 5. 사용자와 비밀번호 구현

서버는 최대 10000명의 사용자를 Users 구조체로 관리한다. Users에는 User 배열, 현재 사용자 수, capacity, array_mutex, 그리고 사용자별 mutex 배열이 있다. 사용자 배열 자체를 검색하거나 새 사용자를 추가할 때는 array_mutex를 사용하고, 특정 사용자의 logged_in 상태를 확인하거나 바꿀 때는 해당 user_mutex를 사용한다.

login 요청에서 username이 처음 등장하면 서버는 새 사용자를 만든다. 이때 password를 그대로 저장하지 않고 hash_password를 이용해 Argon2id hash로 변환한 뒤 저장한다. 이미 존재하는 username이면 validate_password로 입력 password와 저장된 hash를 비교한다. password가 맞고 해당 사용자가 로그인 중이 아니면 logged_in을 true로 바꾼다.

같은 사용자가 동시에 두 client에서 로그인하는 것은 허용하지 않았다. 기존 user의 logged_in 값이 true이면 LOGIN_ERROR_ACTIVE_USER를 반환한다. 또한 하나의 client connection은 하나의 active user만 가질 수 있도록 PollSet에 active_users 배열을 두었다. logout 또는 연결 종료 시에는 active user를 해제하고 서버의 logged_in 상태도 false로 바꾼다.


## 6. 좌석 예약 구현과 동기화

좌석은 100개짜리 Seat 배열로 관리한다. 각 Seat에는 SeatStats, 현재 예약한 사용자 이름, 그리고 좌석별 mutex가 들어 있다. SeatStats에는 좌석 번호, 지금까지 예약에 성공한 횟수, 지금까지 취소에 성공한 횟수가 저장된다.

book 요청에서는 먼저 좌석 번호가 1 이상 100 이하인지 확인한다. 그 다음 요청 사용자가 현재 client의 active user이고 서버에서도 logged_in 상태인지 검사한다. 조건을 만족하면 해당 좌석의 mutex를 잡고, user_who_booked가 비어 있을 때만 예약을 성공시킨다. 예약에 성공하면 user_who_booked에 사용자 이름을 저장하고 amount_of_times_booked를 증가시킨다.

cancel-booking 요청도 좌석별 mutex를 사용한다. 해당 좌석의 예약자가 요청 사용자와 같을 때만 취소를 허용한다. 성공하면 user_who_booked를 해제하고 amount_of_times_canceled를 증가시킨다. 다른 사용자가 예약한 좌석이거나 비어 있는 좌석이면 error를 반환한다.

confirm-booking available은 1번부터 100번까지 좌석을 순회하며 비어 있는 좌석 번호를 모은다. confirm-booking booked는 현재 사용자가 예약한 좌석 번호만 모은다. query는 특정 좌석의 SeatStats를 복사해서 response data로 보낸다. query는 좌석 통계 조회 기능이므로 active user 없이도 실행할 수 있도록 하였다.

Deadlock을 줄이기 위해 lock 순서는 일관되게 유지하였다. 사용자 확인이 필요한 요청은 사용자 배열 lock, 사용자별 lock, 좌석 lock 순서로 처리한다. 좌석별 mutex 덕분에 여러 worker thread가 같은 좌석을 동시에 예약하려 해도 하나의 요청만 성공한다.


## 7. 클라이언트 구현

클라이언트는 server에 TCP connection을 만들고, 사용자 입력을 Request로 바꾸어 보낸다. interactive mode에서는 readline을 사용하고, file mode에서는 getline으로 파일을 한 줄씩 읽는다. 빈 줄은 무시하고, exit 또는 quit이 들어오면 loop를 종료한다.

parse_request는 입력 문자열을 action, username, data로 나눈다. login은 username과 password를 사용한다. book, confirm-booking, cancel-booking, query는 data field를 사용한다. login을 제외한 대부분의 사용자 action은 active user가 필요하므로, active user가 없는 상태에서 book, confirm-booking, cancel-booking, logout이 입력되면 client side에서 먼저 error를 출력하고 서버로 보내지 않는다.

서버 응답은 handle_response에서 처리한다. 성공 메시지는 stdout으로 출력하고 실패 메시지는 stderr로 출력한다. login 성공 시에는 active_user를 저장하고, logout 성공 시에는 active_user를 해제한다. 클라이언트가 exit, quit, EOF로 종료될 때 active user가 남아 있으면 terminate에서 자동 logout request를 서버에 보내고 socket을 닫는다.


## 8. 자원 정리와 종료 처리

서버는 SIGINT handler를 통해 종료 요청을 감지한다. handler는 sigint_received 값을 true로 바꾸고, main thread와 worker thread는 이 값을 확인하여 종료한다. 또한 서버 standard input에서 exit, quit, EOF가 들어와도 같은 종료 흐름으로 들어가게 하였다.

서버 종료 시 terminate_after_cleanup은 worker thread를 깨우고 pthread_join으로 종료를 기다린다. 이후 남아 있는 client socket, pipe fd, PollSet, 좌석 배열, 사용자 배열, mutex, 동적 문자열을 정리한다. 좌석에 예약자가 남아 있으면 user_who_booked를 free하고, 사용자 배열에서는 username과 hashed_password를 free한다.

클라이언트는 매 요청마다 Request와 Response를 free한다. file mode에서 getline이 할당한 line도 처리 후 free한다. 종료 시 socket을 close하고, active user가 있으면 먼저 logout request를 보내도록 하였다.


## 9. 테스트 및 검증

먼저 make clean 후 make를 실행하여 pa3_server와 pa3_client가 정상적으로 빌드되는 것을 확인하였다. 컴파일 옵션에는 -Wall, -Wextra, -Wpedantic, -Werror가 포함되어 있어 warning도 build failure로 처리된다.

업데이트로 제공된 example 1은 pa3_example1.stdin.txt를 클라이언트 입력으로 redirect하여 실행했다. 생성된 stdout.txt와 stderr.txt를 각각 pa3_example1.stdout.txt, pa3_example1.stderr.txt와 diff로 비교했으며, 결과가 모두 일치하였다.

Example 2는 제공된 run-example2-client.sh가 생성하는 client1.stdout.txt, client1.stderr.txt, client2.stdout.txt, client2.stderr.txt를 업데이트된 expected 파일들과 diff로 비교하였다. 두 client가 동시에 login, book, cancel-booking, query를 수행하는 흐름에서 expected output과 일치하는 것을 확인하였다.

동시성 검증을 위해 8개의 client가 같은 seat 77을 동시에 예약하도록 실행하였다. 결과적으로 정확히 한 client만 예약에 성공했고, 나머지는 unavailable error를 받았다. 이후 query 77 결과도 예약 횟수 1회, 취소 횟수 0회로 출력되어 좌석 mutex가 정상적으로 동작함을 확인하였다.

메모리 검증은 ASan/UBSan과 valgrind로 수행하였다. 서버는 valgrind에서 All heap blocks were freed, ERROR SUMMARY: 0을 확인하였다. 클라이언트도 definite, indirect, possible leak이 모두 0 bytes이고 ERROR SUMMARY: 0인 것을 확인하였다.


## 10. 결론

본 구현은 제공된 PA3 skeleton code의 구조를 유지하면서 비어 있던 socket 통신, poll 기반 worker thread, 사용자 관리, 좌석 예약, action handler, 종료 cleanup 로직을 완성한 것이다. 서버는 CPU core 수에 따라 worker thread를 생성하고, 각 worker가 PollSet으로 여러 client socket을 처리하도록 설계하였다.

사용자 배열과 좌석 배열은 mutex로 보호하여 동시성 문제를 방지하였다. 비밀번호는 Argon2id hash로 저장하고, Request와 Response는 field 단위로 안전하게 전송하였다. login, book, confirm-booking, cancel-booking, logout, query action을 모두 구현했으며, 성공과 실패 메시지를 stdout/stderr로 구분하였다.

최종적으로 clean build, 제공 example diff, 동시 예약 테스트, sanitizer 및 valgrind 검증을 통과하였다. 따라서 본 프로젝트는 PA3에서 요구한 design and implementation report의 대상이 되는 핵심 구현을 충족한다.
